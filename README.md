# Game Hub — лендинг

Одностраничный сайт для игрового центра Game Hub (Бендеры, ул. Калинина, 23).
Язык сайта — русский. Без сборки и зависимостей: обычные HTML, CSS и JavaScript.

```
index.html              вся разметка страницы
css/tokens.css          ← ЦВЕТА, ШРИФТЫ, ОТСТУПЫ (менять стиль здесь)
css/styles.css          компоненты и секции
js/main.js              меню, FAQ, галерея, статус «открыто», переключатель сезона
assets/img/             фотографии (3 размера: 640 / 1280 / оригинал)
assets/video/           видео, перекодированные для веба
assets/brand/favicon.svg
Media/                  ИСХОДНИКИ от заказчика (на сайте не используются)
```

---

## Как открыть

Просто откройте `index.html` в браузере — всё заработает.

Для корректной проверки видео лучше поднять локальный сервер:

```bash
python -m http.server 4321
```

затем откройте `http://127.0.0.1:4321`.

## Как поменять фирменные цвета

Весь сайт построен на CSS-переменных. **Ни один компонент не содержит
«зашитого» цвета** — всё берётся из `css/tokens.css`.

Чтобы перекрасить сайт под новый айдентити Game Hub, поменяйте только
блок `[1] BRAND PALETTE` в начале файла:

```css
--brand-primary:   #FFD200;   /* главный акцент, кнопки, цены */
--brand-dark:      #15181D;   /* шапка, тёмные секции, подвал */
--brand-accent:    #7B3FE4;   /* второй акцент: ночные игры, VR */
```

Сейчас стоят цвета с ваших действующих макетов (жёлтый / графит / белый)
как временные. Остальной сайт подстроится автоматически.

> **Важно про контраст.** Цветные метки зон (`--tag-*`) специально затемнены
> относительно постеров, чтобы белый текст на них читался (контраст ≥ 4.5:1,
> норма WCAG AA). Если будете менять эти цвета — проверьте контраст заново,
> например на [webaim.org/resources/contrastchecker](https://webaim.org/resources/contrastchecker/).

Шрифты (Fredoka для заголовков, Nunito для текста) меняются там же,
в блоке `[3] ТИПОГРАФИКА`, плюс ссылка на Google Fonts в `index.html`.

На странице остались два видимых блока-заглушки с пометкой «ожидаем».

заменить ими видео в блоке `.route`.

## Что внутри работает само

- **Статус «открыто / закрыто»** в шапке героя считается от текущего времени.
  Расписание задано в `js/main.js`, объект `SCHEDULE` — правьте только его:

  ```js
  var SCHEDULE = {
    summerMonths: [5, 6, 7],          // июнь, июль, август
    summer:  { open: 10, close: 23 },
    weekday: { open: 12, close: 22 },
    weekend: { open: 10, close: 23 }
  };
  ```

- **Переключатель «Лето / Учебный год»** в секции «Режим работы» сам выбирает
  нужную вкладку по текущему месяцу.
- **Фоновое видео** останавливается, когда герой уходит с экрана (экономит
  батарею и трафик), и имеет кнопку паузы.
- **Год в подвале** проставляется автоматически.

- **Карусель «Шесть направлений»** (секция `#zones`) листается стрелками,
  точками, свайпом, колесом мыши и клавишами ←/→. Сколько карточек видно
  сразу — задаётся в CSS (`.carousel__track`): 1 на телефоне, 2 от 640px,
  3 от 1024px. Кнопки и точки пересчитываются сами, в том числе при
  повороте экрана.

  Стрелки стоят рядом с заголовком (а не под карточками) — так до них не нужно
  пролистывать всю секцию. Точки — под лентой.

  Чтобы добавить направление, достаточно вставить ещё один
  `<article class="zone">` внутрь `.carousel__track` — точки появятся сами.
  Карточки намеренно **без** класса `reveal`: они уезжают за правый край,
  и анимация появления оставила бы их невидимыми.

  **Картинки карточек — строго 16:9** (`.zone__figure`, `aspect-ratio: 16 / 9`).
  Если добавляете новое фото, подбирайте **горизонтальный** кадр: вертикальный
  снимок `object-fit: cover` обрежет по центру и срежет главное.

  На карточке «3D-рисование» стоит `assets/img/zone-3d-*.jpg` — кадр из
  горизонтальной по содержанию части фотографии `photo-27`: дети за общим
  столом, рядом готовые фигурки, на фоне экран Game Hub. Никто не обрезан.

  **Важно про цветную метку.** Метка направления (`.zone__tag`) лежит поверх
  снимка в левом верхнем углу и занимает примерно от 6% до 21% высоты кадра
  и до 35% ширины. Подбирая фото, оставляйте в этой зоне «воздух» — стену,
  потолок, фон, — иначе метка закроет лица. Именно поэтому кадр для
  3D-карточки взят с запасом сверху.

  Портретное фото девочки с 3D-ручкой (`photo-28`) в карточку не помещается
  в принципе: нужная часть кадра — от макушки до рисунка на столе —
  по пропорциям почти квадрат (1,07), а рамка карточки 16:9 (1,78).
  Чтобы показать её целиком, пришлось бы либо добавлять по бокам пустые
  поля, либо делать квадратные рамки и ронять все карточки вниз.
  Поэтому это фото живёт в **галерее**, где рамка квадратная и девочка
  видна полностью.

## Телефоны и планшеты

- `viewport-fit=cover` в `<meta name="viewport">` — **обязателен**: без него
  `env(safe-area-inset-*)` на iPhone возвращает 0, и нижняя панель с кнопками
  заезжает под жест-бар. Боковые отступы контейнера и панели заданы через
  `max(--gutter, env(safe-area-inset-…))`, чтобы в альбомной ориентации текст
  не уходил под «чёлку».
- Галерея на телефоне — **две колонки**: по одному фото в ряд она занимала
  больше пяти экранов прокрутки. Мелкие карточки тарифов там же встают по две.
- Телефон в альбомной ориентации: у героя снимается обязательная высота и
  уменьшается заголовок (медиазапрос `orientation: landscape` и
  `max-height: 520px`), иначе кнопка брони не попадает на первый экран.
  **Важно:** этот блок должен стоять в `styles.css` ПОСЛЕ базовых правил
  `.hero*` — медиазапрос не добавляет специфичности, и при обратном порядке
  правила героя его перебьют.
- Если в телефоне включён режим экономии трафика (или связь 2G), фоновое
  видео (~3 МБ) не загружается — показывается постер, запуск по кнопке.

## Доступность

Проверено на странице:

- контраст текста — **0 нарушений** (проверены все текстовые элементы, порог AA);
- горизонтальной прокрутки нет ни на 375px, ни на 1440px;
- у всех изображений есть описания (`alt`), у кнопок-иконок — `aria-label`;
- заголовки идут по порядку (h1 → h2 → h3), один `h1` на странице;
- кнопки и ссылки — не меньше 44×44px;
- есть ссылка «Перейти к содержимому» для клавиатуры;
- в галерее работают стрелки ←/→ и Escape, фокус возвращается на место;
- при включённой системной настройке «уменьшить движение» анимации отключаются,
  фоновое видео не запускается автоматически;
- **без JavaScript страница полностью читается** — весь контент виден,
  ответы в FAQ раскрыты.

## Медиа

Исходники из папки `Media/` обработаны и лежат в `assets/`:

- **32 фотографии** из HEIC/PNG переведены в JPEG, по три ширины
  (640 / 1280 / оригинал) — браузер сам берёт подходящую через `srcset`.
- **7 видео** были в кодеке HEVC, который **не воспроизводится в Chrome и
  Firefox**. Все перекодированы в H.264:

  | Файл | Было | Стало | Где используется |
  |---|---|---|---|
  | `hero.mp4` | 7,4 МБ HEVC | 2,8 МБ H.264, 1280×720, без звука | фон героя |
  | `clip-01.mp4` | 18,5 МБ HEVC | 6,7 МБ H.264, 1280×720 | видео «Как нас найти» |
  | `clip-02 … clip-05` | 12–22 МБ HEVC/QuickTime | 1,7–2,8 МБ H.264 | в запасе, на странице не используются |

  Один исходник — `IMG_4812 (1).MOV` — встроенный в Windows кодировщик
  преобразовать не смог: файл каждый раз получался битым (без индекса `moov`,
  браузер его не открывает). Он не используется на странице и из `assets/`
  удалён. Если это видео нужно — его можно перекодировать утилитой **ffmpeg**:

  ```bash
  ffmpeg -i "Media/IMG_4812 (1).MOV" -c:v libx264 -crf 23 -preset slow          -vf scale=1280:-2 -c:a aac -b:a 96k -movflags +faststart          assets/video/clip-06.mp4
  ```

- Постер героя `hero-poster.jpg` и фото зоны VR — настоящие кадры из видео
  (показывается, пока видео грузится, чтобы не было пустого экрана).

> **Если будете перекодировать видео сами:** проверяйте, что в готовом файле
> есть бокс `moov` — мультиплексор пишет его последним, и при прерывании
> получается файл правильного размера, который браузер открыть не может.
> Для ffmpeg это решает флаг `-movflags +faststart`.

Папку `Media/` на хостинг загружать не нужно — это архив исходников.

### Если добавляете новые фото

Кладите в `assets/img/` в двух размерах (`-640.jpg` и `-1280.jpg`) и
подключайте так же, как соседние — с `srcset`, `width`, `height`,
`loading="lazy"` и осмысленным `alt`. Атрибуты размеров обязательны:
без них страница «прыгает» при загрузке.

1. **Режим работы.** На постере `Media/ChatGPT Image 11 сент…` указано
   «Пн–Пт 12:00–22:00, Сб–Вс 10:00–22:00», а в вашем брифе — «Сб–Вс до 23:00»
   и «летом ежедневно 10:00–23:00». На сайте стоят данные **из брифа**.
   Если верен постер — поправьте `SCHEDULE` в `js/main.js` и текст в секции
   «Режим работы» и в подвале.

2. **Телефоны.** В брифе основной номер — `0 778 95 477` (Татьяна).
   На постере есть второй — `0 778 73 236` (Никита); он добавлен в подвал.
   Украинский номер и почта в брифе отмечены как относящиеся к социальной
   работе, поэтому на коммерческий сайт не вынесены.

3. **Telegram.** Ссылка сейчас ведёт на `t.me/+37377895477`. Если у центра
   есть именной аккаунт (например `t.me/gamehub`), замените — так надёжнее.

4. **VR-фото.** Отдельных фотографий VR-зоны в папке не было, поэтому для
   карточки VR взят кадр из вашего же видео. Как появятся снимки — замените.

5. **Instagram.** Везде стоит новый аккаунт
   [@gamehub_bender](https://www.instagram.com/gamehub_bender/).
   Если старый `@gamehub.neonloft` ещё работает, имеет смысл поставить
   на нём ссылку-переадресацию на новый.

6. **WhatsApp убран** по вашей просьбе — остались звонок, Telegram и Instagram.
   Если решите вернуть, достаточно продублировать кнопку Telegram в секции
   `#booking` и иконку в подвале (иконка `#i-whatsapp` в спрайте сохранена).

7. **Логотип.** Сейчас в шапке — текстовый логотип со значком геймпада,
   собранный из фирменных цветов. Это временное решение до нового айдентити
   Game Hub: достаточно будет подставить готовый SVG вместо блока `.logo`.
